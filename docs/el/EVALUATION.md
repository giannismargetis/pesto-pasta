# Αξιολόγηση: μεθοδολογία και αποτελέσματα

Κάθε ισχυρισμός στηρίζεται σε αναπαραγώγιμη μέτρηση (`research/results/`). Βασική
γραμμή (baseline) = ο αρχικός κώδικας στο commit `d6799d0`, με το αρχικό `config.json`.
Υλικό: RTX 3050 8 GB, Windows 10, Python 3.13.

## 1. Ακρίβεια αναγνώρισης ομιλίας — `research/asr_eval.py`

* **Δεδομένα**: FLEURS (Conneau et al., 2022, CC-BY-4.0), σύνολο ελέγχου, ελληνικά και
  αγγλικά. Μία ηχογράφηση ανά διαφορετική πρόταση, ανακάτεμα με σταθερό seed
  (20261004), 200 εκφωνήσεις ανά γλώσσα (`research/data/manifests/`).
* **Μετρικές** (`research/metrics.py`, με unit tests):
  * WER/CER σε **επίπεδο σώματος** (σύνολο σφαλμάτων / σύνολο λέξεων αναφοράς), μετά από
    κανονικοποίηση πεζών/στίξης (ενοποίηση τελικού σίγμα)·
  * CER χωρίς τόνους — η διαφορά από το CER απομονώνει τα λάθη τονισμού·
  * «μορφοποιημένο» WER: με πεζά/κεφαλαία και στίξη, δηλαδή αυτό που λαμβάνει ο χρήστης.
* **Αβεβαιότητα**: διαστήματα εμπιστοσύνης 95 % με bootstrap (2000 επαναδειγματοληψίες,
  σταθερό seed)· συγκρίσεις ζευγαρωτά (paired bootstrap + Wilcoxon) στις ίδιες εκφωνήσεις.
* Κάθε διαμόρφωση τρέχει σε **ξεχωριστή διεργασία**.

| Διαμόρφωση | WER ελληνικά | WER αγγλικά | CER ελληνικά |
|---|---|---|---|
| Αρχικό Whisper (auto, beam 2, VAD, ελληνικό prompt) | 12,61 % [11,1–14,3] | **51,02 %** | 4,91 % |
| Νέο Whisper, beam 1 | 13,09 % | 5,54 % | 5,11 % |
| **Νέο Whisper, beam 2 (προεπιλογή)** | **12,28 % [10,8–14,1]** | **5,52 %** | 4,57 % |
| Αρχικό Parakeet (int8, CPU) | 42,82 % | 9,53 % | 17,45 % |
| Νέο Parakeet (fp32, CUDA) | 34,88 % | 5,96 % | 11,30 % |

* Ελληνικά, νέο (beam 2) έναντι αρχικού: ΔWER −0,34 μονάδες [−1,01, +0,35] — ισοδύναμο.
  Beam 2 έναντι beam 1: −0,82 [−1,39, −0,36] (στατιστικά σημαντικό).
* Αγγλικά: 51,0 % → 5,5 %. Αιτία της βελτίωσης: το prompt επιλέγεται μετά την αναγνώριση
  γλώσσας (περιορισμένη σε ελληνικά/αγγλικά).
* Το Parakeet δεν έχει τελικό σίγμα στο λεξιλόγιό του· το 17,7 % των ελληνικών λέξεων
  τελειώνει σε ς. Ακόμη κι αν αυτό αγνοηθεί, το WER του θα ήταν ~31 %.

## 2. Καθυστέρηση μηχανής — `research/latency_ab.py`

Η καθυστέρηση σε επιτραπέζια GPU μεταβάλλεται με το υπόλοιπο φορτίο. Γι' αυτό οι δύο
διαμορφώσεις **δεν** μετρώνται σε διαφορετικές στιγμές: μεταγράφουν το **ίδιο** απόσπασμα
η μία μετά την άλλη, με εναλλασσόμενη σειρά (ABBA), και αναλύεται η ζευγαρωτή διαφορά.
Αποσπάσματα: 50 ελληνικά + 50 αγγλικά, ολόκληρα και τα πρώτα 3 s (μήκος push-to-talk).

| Αποσπάσματα | Αρχικό p50 / p95 | Νέο p50 / p95 | Διάμεση διαφορά [95 % CI] |
|---|---|---|---|
| 3 s (n = 78) | 804 / 859 ms | **450 / 502 ms** | −351 ms [−357, −346] |
| ολόκληρα ≈10 s (n = 97) | 990 / 1332 ms | **562 / 879 ms** | −383 ms [−390, −377] |

Wilcoxon p < 10⁻¹⁵· το νέο ήταν ταχύτερο στο 98–100 % των αποσπασμάτων.
Το αρχικό σύστημα επέστρεψε **κενό** κείμενο σε 21 από 50 αγγλικά αποσπάσματα 3 s.

* **Ψυχρή εκκίνηση** (από την εκκίνηση διεργασίας ως το πρώτο κείμενο): 8,1 s → **4,4 s**.
* **Πλήρης εκκίνηση εφαρμογής** (hook + μικρόφωνο + μοντέλο έτοιμα): ~4,2 s.
* **Πύλη ομιλίας**: ~4 ms για 3 s ήχου· ένα κενό πάτημα κοστίζει χιλιοστά αντί για ~450 ms.
* **Imports**: ~5,4 s με PyTorch → ~0,7 s χωρίς.

## 3. Καθυστέρηση στην πραγματική χρήση — τηλεμετρία

Ο πίνακας `interactions` (`data/pesto.db`) αποθηκεύει για κάθε υπαγόρευση την
καθυστέρηση από το άφημα ως το κείμενο και από το τέλος της ομιλίας ως το κείμενο, με
ανάλυση (αναμονή, πύλη, ASR, δρομολόγηση, πρόσθετη καθυστέρηση, εισαγωγή). Αυτή είναι
η μέτρηση που πρέπει να αναφέρει η διπλωματική για την **αντιληπτή** καθυστέρηση· η
καθυστέρηση μηχανής είναι μόνο ένα συστατικό της. Δεν υπάρχουν ακόμη δεδομένα χρήσης.

## 4. Κατανόηση εντολών — `pasta/eval/nlu.py`

201 επισημασμένες εκφωνήσεις: οι 56 του παλιού benchmark (`legacy`), 25 που
χρησιμοποιήθηκαν στη συγγραφή της γραμματικής (`dev`), και 120 γραμμένες **πριν** την
πρώτη αξιολόγηση και όχι για ρύθμιση (`heldout`, εκτός πεδίου `heldout_oos`, και
«παγίδες» υπαγόρευσης `dictation`).

| Υποσύνολο | Πρώτη εκτέλεση (αθέατα) | Μετά από διορθώσεις (post-hoc) |
|---|---|---|
| Εντολές held-out, ελληνικά | 97,5 % ακριβής αντιστοίχιση | 100 % |
| Εντολές held-out, αγγλικά | 85,0 % | 100 % |
| Απόρριψη εκτός πεδίου | 80 % (οι 2 αποτυχίες απέτυχαν ασφαλώς στη γείωση) | 100 % |
| Υπαγόρευση που εκλήφθηκε ως εντολή | **0 %** (30 παγίδες) | 0 % |

Χρόνος ανάλυσης: 0,06 ms (διάμεσος). Η επιτυχία εκτέλεσης σε πραγματική επιφάνεια
εργασίας μετριέται με `python -m pasta.eval.live` (δεν έχει τρέξει ακόμη).

## 5. Γιατί οι παλιοί αριθμοί δεν ήταν μετρήσεις

* Το «100 %» του PASTA v2 αξιολογούσε υποψήφιες ενέργειες που παράγονταν από λέξεις-κλειδιά
  με ετικέτες από τις ίδιες λέξεις-κλειδιά (κυκλικό), και ο επαληθευτής επέστρεφε επιτυχία
  σχεδόν πάντα.
* Το ελληνικό benchmark του PESTO v5 μεταγράφε **σιωπή** και, όταν η έξοδος ήταν κενή,
  χρησιμοποιούσε την αναφορά ως υπόθεση — 0 % WER εκ κατασκευής.
* Οι τιμές 193–348 ms δεν αναπαράγονται με τις ρυθμίσεις που διανεμόταν (τα logs
  έδειχναν 650–950 ms ανά μεταγραφή).

## Περιορισμοί

* Το FLEURS είναι ανάγνωση (~10 s ανά πρόταση)· η υπαγόρευση είναι αυθόρμητη και πιο σύντομη.
* Οι αριθμοί γράφονται με ψηφία στις αναφορές· διαφορές μορφοποίησης αριθμών μετρούν ως λάθη.
* Δεν υπάρχει ακόμη σώμα δεδομένων ελληνικών με εναλλαγή αγγλικών όρων· μπορεί να
  ηχογραφηθεί με την πλατφόρμα μελέτης (`experiment.save_audio`).
